# Lakes Surf — notes for Claude Code

Great Lakes surf-forecast PWA. One file does everything: `index.html` (HTML + CSS + ~3,400 lines of inline JS). No build step, no framework, no backend. Hosted on GitHub Pages from `main`; installed as a PWA on phones.

## Release checklist (every change)

1. Bump the version: `const CACHE = 'lakes-surf-v5_11_14';` in `service-worker.js` → next number. Nothing else carries the version.
2. Syntax-check the inline script before committing (there is no linter in the repo):
   ```bash
   python3 -c "import re;s=open('index.html',encoding='utf-8').read();open('/tmp/inline.js','w').write('\n'.join(re.findall(r'<script(?![^>]*src)[^>]*>(.*?)</script>',s,re.S)))" && node --check /tmp/inline.js && node --check service-worker.js
   ```
3. Smoke-test in a headless browser if the change touches rendering (Playwright is fine; mock the external APIs, they're all blocked/flaky from sandboxes).
4. Commit as `vX.Y.Z` and push `main`. The old Evanston cam ID `qv5XF6USv7M` must appear only in the `loadState()` migration and `CAM_NO_EMBED`.

Line endings: the working copy on Windows is CRLF; `.gitattributes` has `* text=auto`, so git normalizes to LF. Don't fight it.

## External data (all called straight from the browser, no API keys)

- **Forecast**: NOAA `api.weather.gov/points/{lat},{lon}` → `forecastGridData`. A coordinate on land gets a grid cell with no wave data, so built-in spots sit a few hundred metres offshore (e.g. Bradford Beach is at `-87.866`, not the beach's `-87.873`). When adding a spot, probe the gridpoint and check `waveHeight.values` isn't a single `0`. User-added spots do this automatically on save (`findForecastPoint()`): if the pin's cell has no waves, the forecast comes from a point stepped out into the lake, stored as `spot.fcLat/fcLon` while `lat/lon` stays the pin; always fetch forecasts via `forecastLatLon(spot)`.
- **Hourly weather icons** (Forecast tab's WX column): `wxKind()` + `wxIcon()` copy weather.gov/greatlakes's own rules (its script picks icons from the grid, NOAA serves no icon data): sky cover <30% sun/moon, >70% cloud, else partly; `fog` in the grid's `weather` field → fog; with precip chance ≥30%, thunder > snow > rain. Night is the spot's true sunset→sunrise (`isDaytimeAt()`, zenith 90.833; that page uses a fixed 7 PM–6 AM). Icons are our own flat SVGs (`WX_ICONS`). NOAA's `forecastHourly` text is no longer fetched; its `isDaytime` is a fixed 6 AM–6 PM.
- **Live obs**: GLOS Seagull (Great Lakes Observing System, free, no key; https://seagull.glos.org). Its API isn't documented; these are the calls its own site makes, and only `api/v1` and `api/v2` allow other origins (`api/v3` and `seagull-cdn-api` are locked to seagull.glos.org; ERDDAP and NDBC's own files send no CORS headers). `api/v2/obs-latest?collectionStatus=active` = every station's newest values (~350 KB, cached 5 min); `api/v2/obs?startDate=YYYY-MM-DD&obsDatasetId=..&parameterIds=..` = time series (date only, UTC; qartod flags are all 9, ignore them). Values are SI (m, m/s, K); `glosStation()` converts them to ft / mph / °F and reshapes each station into the old Synoptic station object (`STID`, `NAME`, `OBSERVATIONS.<var>_value_1`), so the picking/display code didn't change. Readings older than 3 h are dropped for spots (3 days for the Buoys tab). Mapping a station's parameter ids to readings needs GLOS's 3.6 MB parameter list, so `.github/scripts/glos-stations.mjs` (hourly, same workflow as GLERL) writes `data` branch `glos/stations.json` (~70 KB: dataset id `d`, `id` = NOAA number when it has one else GLOS's code, name, lat/lon, lake, `type`, `out` = recovered, `p` = var → parameter id; inland lakes/rivers filtered out). Lakefront C-MAN/NOS wind (CHII2, OKSI2, MCYI3…) lands ~1–1.5 h late; Spotters ~20–45 min. No airport ASOS in GLOS. Lakefront stations GLOS lacks come from weather.gov (`NWS_LAKE_STATIONS`: CNII2 Northerly Island for Promontory, SGNW3 Sheboygan harbor; `stations/{id}/observations`, CORS-open, km/h and °C, ~1–2 h behind, wind often missing from a report so the newest report that has it is used; fetched only within 30 mi of a saved spot; `nwsWindTimeseries()` for their charts). To add one, check its observations actually carry `windSpeed` (CHII2's are all null on weather.gov). Many buoys are pulled out of the water Nov–Apr.
- **Switching back to Synoptic** (live obs used Synoptic/Mesowest until v5.47.2, commit `796f59c`; the free 14-day trial on the app's account ended 2026-11-12 and Open Access needs a .edu email; the owner has asked Synoptic about free access): restore from `796f59c` the constants `MESOWEST_BASE`/`MESOWEST_TOKEN` (token `023f91656dc9434ea8f1c89f810a53cd`, still listed on the account; check it isn't 403 first), `LAKE_MI_BBOX`, `stationsBbox()` + the Synoptic `fetchAllLakeStations()`, `fetchWaveTimeseries()` and `loadBuoyLive()` (+ `GREAT_LAKES_BBOX`, the NDBC footer link), and the Settings credit. Everything downstream already speaks Synoptic's station shape; `stationTier()` still has the MNET_ID tiers. Never use the token from weather.gov/greatlakes's page (it's NOAA's paid access).
- **Map heat map**: NOAA NDFD WMS, same layers as weather.gov/greatlakes. Image overlay, one request per frame:
  `https://digital.weather.gov/ndfd/wms?SERVICE=WMS&VERSION=1.3.0&REQUEST=GetMap&FORMAT=image/png&TRANSPARENT=TRUE&EXCEPTIONS=INIMAGE&STYLES=&REGION=conus&CRS=EPSG:3857&LAYERS=ndfd.conus.{waveheight|windspd|windgust}&VTIT={valid}_{issuance}&BBOX={EPSG:3857}&WIDTH=..&HEIGHT=..`
  Valid times come from `https://www.weather.gov/source/dlh/ndfd_times.json` (CORS `*`); never invent a VTIT — unknown times silently return a default map. Legend: `digital.weather.gov/scripts/wxmap_legendImage.php?dataset=ndfd&element=..&ms=english|nautical|metric&...`. The WMS has no CORS, so it only works as `<img>`, never `fetch()`. `ndfd.conus.windspd.windbarbs` exists but draws on an opaque grey background — unusable.
- **Wind/gust layers on the map**: drawn locally (not NDFD) as a Windfinder-style color field + animated streaks on canvases in a `windPane`, from Open-Meteo (CORS open, multi-point): `api.open-meteo.com/v1/forecast?latitude=a,b,..&longitude=..&hourly=wind_speed_10m,wind_direction_10m,wind_gusts_10m&forecast_days=7&wind_speed_unit=mph&timezone=UTC&timeformat=unixtime` on the 0.5° `WIND_GRID` (684 points, fetched in chunks of 240, cached 1 h). See `loadWindGrid()`, `windRedraw()`, `windStep()`. Colors are clipped to the lakes using `great-lakes.json` (Natural Earth 10m lakes v5.1.2, public domain, Douglas-Peucker simplified to 0.005°, coords rounded to 3 dp; array of `[lon,lat]` rings incl. islands, drawn with even-odd fill). It's in the service worker's `SHELL` list.
- **Map source switch**: one Smooth / NOAA switch for all three layers, `state.mapSource` (`'blend'` default / `'noaa'`; falls back to the older wave-only `state.waveMapSource`). Smooth = canvas fields from Open-Meteo: wind grid above, and waves from Open-Meteo marine `marine-api.open-meteo.com/v1/marine?...&hourly=wave_height,wave_direction` on `WAVE_GRID` (1/4° × 1/3°, only points in a lake or nearest its shore, ~490 points), with streaks kept to the water that move at the deep-water crest speed g·T/2π from `wave_period` (also fetched; `WAVE_STREAK_SPEED` is only the fallback when period is missing). NOAA = the NDFD WMS images (wave, windspd, windgust). Colors: `WAVE_STOPS_FT` (NOAA's 1-ft wave bands, used banded for NOAA and blended for Smooth), `NOAA_WIND_STOPS_MPH` (NOAA wind legend, transcribed by eye), `WIND_STOPS_KT` (Windfinder-style, Smooth wind). The legend (`fieldUpdateLegend()`) is drawn locally for every layer. Tap readouts: Smooth samples the grid (with direction); NOAA calls `getForecast()` for the tapped point (~2 s). Tapping again closes the reading (`closePopupOnClick: false` + own click handler).
- **Open-Meteo rate limits**: every grid point counts as an API call (free tier ≈ 10k/day, a few thousand per hour, per device). Grids go through `fetchJsonCached()` (Cache Storage `lakes-surf-data`, 1 h, survives SW version bumps) and load only when their layer is shown. Testing repeatedly from one machine can hit 429s. The wave layer is still the NDFD WMS. NOAA's NDFD point XML client is NOT CORS-open, don't try it.
- **Pin names**: a dropped pin's suggested name comes from OpenStreetMap Nominatim (`suggestSpotName()`): nearest named beach ≤1.6 km, else park ≤1 km, else town. Plain reverse geocoding returns roads/footpaths. Max 1 request/s (usage policy). Overpass was too slow (15 s timeouts); Google needs a billed key and its terms forbid showing its data on OSM maps.
- **Place search** (Add sheet and Map tab): as you type (300 ms pause, 3+ letters) via Photon `photon.komoot.io/api/` (OSM data, CORS open, built for search-as-you-type, fair use), bounded to the Great Lakes, streets/shops/etc. excluded server-side (`PHOTON_EXCLUDE`, otherwise they crowd parks out of the top results), biased to the map centre or the saved spots' middle. Lakeshore results first (`nearGreatLake()`). `spot: true` = a beach/park/pier/lighthouse within 2.5 km of a lake: it opens the Add form directly (`addSpotFromPlace()`, which moves a pin >300 m from the water to the nearest lake edge, since big parks' centres are inland); towns etc. open the map there in pin mode. Each result row is a name button plus an optional Add/Map pill (`placeRow()`); on the Map tab tapping the name flies there and Add adds (`mapSearchAdd()`). Search boxes have their own clear ✕ (`.search-wrap`, shown via `:placeholder-shown`). New installs start with Montrose, Greenwood and Sheboygan (`FIRST_RUN_SEED`). Results within 1 mi of a popular spot are hidden in favour of it (`nearPopularSpot()`). Saved and built-in spots match instantly from 2 letters (`mapSearchLocal()`, `nameMatches()`). Nominatim forbids search-as-you-type, so it's only the fallback when Photon fails on Search/Enter.
- **Adding spots**: the Spots tab's + opens the Add sheet (`openPopularSpotsModal()`, `#modal-popular`): search box, popular spots filtered by it, other places below, "Drop a pin on the map" link. The spot form has a mini map (`spotFormMap`, draggable pin / tap to move) instead of lat/lon boxes, which sit under "Edit coordinates"; the cam URL is under "More options".
- **Buoys tab** (`view-buoys`, header switch Live | Fcst; buoys are picked by tapping the maps, and Fcst opens on the Live buoy, or the nearest forecast buoy with a note when GLERL has none for it; `state.buoyMode`, `applyBuoyMode()`, `renderHeader()`; one shared `state.buoyId`, the 45xxx id; both views fit one screen: the maps take what the card leaves, `.buoy-map-wrap` flex with a min height, re-framed on resize until the user moves them). **Live**: every Great Lakes wave buoy in GLOS (`loadBuoyLive()`: `type` moored_buoy with a wave-height parameter, Spotters included, pulled-for-season ones too), from the same station list + obs-latest as the spot readings. In ≤3 h, Quiet 3 h–3 days, Out otherwise or when GLOS lists it as recovered. Ids are NOAA numbers where there is one (Spotters too, e.g. 45214), else GLOS codes like `SPOT-1563`; the footer links GLOS's data console. The card reuses the spot Live tab's charts (`liveChartsHtml()`, `compact` drops the direction labels): any change to the buoy Live charts goes on the spot Live tab too (user's rule). Live and Fcst charts share one look: "Waves (ft)" / "Wind (mph)" titles, 120 px, a `chartKey()` legend, blue main line + `CHART_AMBER` second line, vertical gridlines (3-hourly on Live, daily on Fcst). Both Buoys views use Live's name/position for a buoy (`buoyInfo()`) and status-colored dots with a white ring on the selected one (`markBuoySelected()`). **Forecast**: NOAA GLERL's experimental point-ensemble wave forecast (`https://www.glerl.noaa.gov/emf/waves/WW3/?pg=xgb<id>`), 24 buoys, 10 days hourly, runs 00Z/12Z. GLERL sends no CORS headers, blocks framing, and each buoy's Plotly JSON is ~590 KB, so `.github/workflows/glerl-outlook.yml` runs `.github/scripts/glerl-outlook.mjs` (Node, no deps) hourly at :20 (GLERL posts runs anywhere from ~2 to 10+ h after 00Z/12Z) and force-pushes trimmed files (~11 KB each: wave avg/p10/p25/p75/p90/xgb/ww3 in ft, wind avg/hrrr in mph, wind dir in degrees FROM, taken from the ensemble wind bars' hover data, 8 compass points; drawn as an arrow row at local midnight/noon) to the `data` branch; the app reads `raw.githubusercontent.com/ekrienik/lakes-surf/data/glerl/index.json` and `<id>.json` (CORS open) through `fetchJsonCached` (30 min). The buoy list comes from the page's inline `{desc, coords, src}` objects. GLERL publishes no wind range, so the wind chart is two lines. WW3 covers 3 days, XGBoost and HRRR+GFS 5. Charts: `buoyChart()` reuses the Live charts' touch readout (`lineChartData[..].readout` overrides the wording). Scheduled workflows pause after 60 days without repo commits.
- **Water quality**: Chicago Data Portal `2ivx-z93u` (Chicago Park District beaches only, Memorial Day–Labor Day). Grade only shown when the sample is ≤24 h old.
- **Water temp fallback**: NWS OMR bulletins via api.weather.gov products.
- **Basemap**: OpenStreetMap tiles everywhere (Map tab and both spot mini-maps). CARTO basemaps now show an "API KEY REQUIRED" watermark; don't reintroduce them.
- **Cams**: YouTube IDs via `extractYouTubeId()` (handles watch/embed/v/live/shorts/youtu.be). `CAM_NO_EMBED` lists IDs whose owners block iframes (open in new tab instead). Evanston Dempster St is `live/xrqe-P1uT_I`, backup webcamtaxi link in `camAlt`.

## Conventions

- Units live in `state.units` (`wave` ft/m, `wind` mph/kt/km/h, `temp` F/C); format with `fmtWave()/fmtWind()/fmtTemp()`. Internally waves are metres, wind km/h, from NOAA; live readings are converted to ft/mph/°F on arrival (`glosStation()`) and back via `obsFtToM()` etc.
- `dirArrow(deg)` draws a FROM-direction arrow pointing where the wind/swell goes (rotates deg+180).
- Spot ids: saved `sp_xxxx`, built-ins keep `builtinId: 'pop_*'` so migrations can find them.
- External links get `rel="noopener"`. All user/station strings go through `escapeHtml()`.
- Service worker: cross-origin requests are never intercepted; the page is network-first, other shell files cache-first. It was silently broken (missing `});`) before v5.11.14 — if PWA updates seem stuck, check it parses.

## Testing tips

- Playwright headless works well: route `unpkg.com/leaflet*` to a local copy, mock `api.weather.gov/points` + `gridpoints`, `seagull-api.glos.org`, `open-meteo`, `ndfd_times.json`, and return a 1×1 PNG for tile/WMS hosts. Use an iPhone device profile for touch tests (chart readout uses touch events).
- To force a forecast page: `state.spots=[...]; saveState(); openForecast(id)`. To force the map: `switchView('map')`.
